## Рекомендуемый порядок улучшений

Этот порядок ориентирован на постепенное устранение сначала функциональных и потоковых ошибок, затем проблем устойчивости и только после этого — косметического техдолга. Не объединять все этапы в один большой рефакторинг.

### Общие правила выполнения

- Каждый этап выполнять отдельной задачей и небольшим PR; внутри этапа допускается делить независимые изменения на ещё меньшие PR.
- Каждое исправление сопровождать регрессионным тестом, который воспроизводит исходную проблему. Тест на новое правильное поведение добавлять вместе с исправлением, а не оставлять в ветке заранее падающий тест.
- Не переписывать legacy-код, не связанный с текущим этапом; не проводить массовую замену `self.model`, списков состояний или архитектурных границ без отдельной задачи.
- Новые зависимости добавлять только после согласования с пользователем. Для предлагаемых исправлений новые runtime-зависимости не требуются.
- После каждого этапа запускать `uv run pytest -v`; Ruff check/format выполнять по конвенции проекта только для затронутых файлов с `--config=./linter_ruff.toml`.
- GUI, трей, MCI-звук, screensaver/video monitor и WinAPI дополнительно проверять вручную на Windows. Зелёный Linux pytest не подтверждает корректность этих частей.
- При существенном изменении архитектуры, FSM, настроек или тестов обновлять `.agents/memory/`, граф знаний и связанные документы.

### Этап 2. Установить единую потоковую модель

**Связанные пункты:** 3, 11, 15.

## Ловушки для агента

- **CWD обязателен — корень проекта**: относительные пути `res/img/`, `res/sounds/`, `./settings/`, `./logs/` ломаются при запуске из другого каталога.

  (`support/sound/windows/sound_player.py`, импортируется фабрикой только на win32) на Linux
  не работают — их не импортировать в тестируемые на Linux модули без изоляции.
- ~~**`playsound==1.3.0`** — старый пакет, известен проблемами на некоторых системах; замена — только по согласованию.~~ Решено: с v2.2.0 заменён собственным MCI-плеером (`src/support/sound/windows/`), зависимость и vendored wheel удалены.
- Тесты GUI отсутствуют: на Linux (агентная среда) можно гонять только не-GUI тесты; ручная проверка GUI — только на Windows.
