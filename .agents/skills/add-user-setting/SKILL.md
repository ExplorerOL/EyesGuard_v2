# add-user-setting

Добавь новую пользовательскую настройку сквозным путём по всем слоям приложения.
Частичная реализация (только поле в dataclass или только виджет) — незавершённая
работа; скилл доводит настройку до теста и документации.

Контекст и подробности слоёв: `.agents/memory/app/settings.md`,
`.agents/memory/prj/architecture/overview.md`.

## Чеклист шагов (обязательный порядок)

1. **Модель данных** — `src/config/settings.py`:
   - поле в `UserSettingsData` со значением по умолчанию;
   - поле в `SettingsDataValidator` (pydantic): тип, ограничения (`Field(gt=..., lt=...)`
     или `Literal["on", "off"]` для on/off), тот же дефолт.
   - Валидация обязательна: битый settings.json должен переживаться на дефолтах.
2. **Виджет** — `src/windows/wnd_settings.py`:
   - виджет по образцу существующих (CTkCheckBox для on/off, CTkEntry+валидация для чисел);
   - инициализация значением из `Settings`.
3. **Чтение из UI** — `src/view.py`, метод `__get_user_settings_from_wnd_settings`:
   - чтение значения виджета в соответствующее поле `UserSettingsData`
     (int(...) / str(...) — по образцу соседних строк).
4. **Использование в логике** — место по смыслу настройки:
   - тайминги → `Model.__init_steps` (пересчёт `steps_data_list`);
   - поведение шагов → `Model.do_current_step_actions` / `wait_for_current_step_is_ended`;
   - уведомления → проверка `notifications`, звук → образец `SoundNotificator`
     (проверка `sounds` через `OnOffValue.on.value`).
5. **Тест** — `tests/test_settings.py`:
   - граничные значения (валидные min/max, невалидные) — параметризацией;
   - при необходимости fixture-JSON в `tests/data/` по образцу существующих;
   - прогон: `uv run pytest` (из корня).
6. **Документация** — довершение скилла:
   - обновить таблицы в `.agents/memory/app/settings.md` (поле, тип, дефолт, границы);
   - дополнить сущность `Settings` графа знаний (`memory_add_observations`);
   - строка в `CHANGELOG.md` (кратко).

## Правила стиля (напоминание)

- Логирование: `logger.trace("Class: method_name")` первой строкой нового метода.
- Приватные поля `self.__name`, вызовы с именованными аргументами.
- on/off значения — строки "on"/"off" (enum `OnOffValue`), не bool: формат JSON настроек исторический.
- Код, комментарии, docstrings — на английском; документация — на русском.
- Новый чекбокс в `WndSettings` не писать без пункта 3 (чтение из UI) — настройка «теряется».

## Границы

- Системные константы таймингов (`SystemSettingsData`, UPPER_SNAKE_CASE) — не пользовательские
  настройки: менять напрямую в коде, без UI и без pydantic (вне этого скилла).
- Если настройка требует нового типа виджета или новой логики окна — согласуй дизайн с пользователем.
