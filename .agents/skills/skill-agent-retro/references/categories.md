# Категории анализа (чек-лист ретро)

Пройти каждую. Формат вывода: находка ИЛИ «ничего, потому что ...».

## 1. Тул-экономика

**Use when**: секция TOOL_CALLS показывает дубли, длинные конвейеры, перевес
bash+grep над специализированными инструментами.

Типовые находки:
- Много `grep`/`rg`/`cat`/`head` в проектах с codegraph — заменить на
  `codegraph_codegraph_explore` (один вызов вместо цикла grep+read)
- Повторяющиеся `head -N` после инструментов, которые уже усекают вывод
- Точные дубли команд >=3 раз — кандидат на команду/скрипт или фиксацию в памяти
- Длинные конвейеры `a | b | c | d` — кандидат на маленький скрипт в репо
- `cat` целых файлов там, где хватает serena `get_symbols_overview` / read с offset

Фикс: правило в AGENTS.md, правка промпта скилла, скрипт-хелпер.

## 2. Скиллы и конфликты

**Use when**: секция SKILL_CONFLICTS непуста; в контексте сессии скилл не сработал
или сработал зря; пользователь звал скилл, а триггер не попал.

Типовые находки:
- Одно имя в нескольких местах (глобально `~/.agents`, `~/.claude`, в каждом
  проекте `.agents/skills`, worktree) — оставить один канонический экземпляр,
  остальные удалить после сверки diff
- Description без триггер-фраз пользователя → дописать фразы
- Два скилла пересекаются по зонам → разграничить в descriptions

Фикс: удаление дубля, правка frontmatter, слияние содержимого (diff перед этим).

## 3. Ошибки и ретраи

**Use when**: level=ERROR > 0, stream error > 0, `error=Aborted` в PROCESS-строках.

Типовые находки:
- Повторяющийся `error=Aborted` на одной сессии — нестабильность провайдера/модели,
  кандидат на смену модели или разбор инцидента
- stream error после больших контекстов — кандидат на /compact раньше

Фикс: заметка в журнале, при систематике — правило в AGENTS.md (например,
«после N токенов предупреждать о компакции»).

## 4. Навигация

**Use when**: в дублирующихся командах виден поиск вслепую — много `ls`,
`glob`, `grep -r` по одним и тем же местам, `resolved path`/`loading path` циклы.

Типовые находки:
- Одни и те же пути ищутся в каждой сессии → pointer в AGENTS.md или заметка
  в графе знаний
- `loading path` на несуществующие конфиги (например opencode.json и .jsonc
  одновременно) — безвредно, но фиксируется как шум

Фикс: короткая секция «карта проекта» в AGENTS.md, сущность в графе знаний.

## 5. No-ops (мёртвые инструкции)

**Use when**: AGENTS.md большой; правила не влияют на наблюдаемое поведение.

Типовые находки:
- Инструкция дублирует дефолт инструмента
- Инструкция противоречит фактическому поведению (проверяется по логам:
  например, «использовать serena» при фактическом grep)
- Противоречия между глобальным и проектным AGENTS.md

Фикс: удаление/уточнение правила, перенос механических проверок в линтер.

## 6. Память и граф знаний

**Use when**: в проекте есть `.agents/memory/` или граф знаний (memory_*).

Типовые находки:
- Существенные изменения (клиенты, фикстуры, CI) сессии не отражены в графе —
  предложить memory_add_observations / обновление md-заметки
- Устаревшие наблюдения (противоречат текущему коду)

Фикс: добавить наблюдения через memory_*, обновить md-заметку (источник истины).

## 7. Разрешения (ASKING)

**Use when**: asking > 5 за сессию.

Типовые находки:
- Повторяющиеся ask на одни и те же безопасные паттерны → предложение дополнить
  permission-правила в opencode.json (edit ask → allow для конкретного паттерна)

Фикс: секция permission в opencode.json, только по явному согласию пользователя.
