# skill-agent-retro

Ретроспектива сессии: сбор фактов из логов opencode → анализ по категориям →
отчёт с кандидатами на улучшение → правки по подтверждению → журнал уроков.

## Быстрый старт (краткая инструкция)

1. Пользователь: «проведи ретро сессии» (текущая/последняя сессия проекта),
   «ретро сессии за 7 дней» (окно) или «ретро сессии <ses_id>».
2. Запусти сбор фактов:
   `bash .agents/skills/skill-agent-retro/scripts/collect.sh --last`
   (варианты: `--session <ses_id>`, `--window <Nd>`).
3. Прочитай [references/categories.md](references/categories.md) и пройди все категории анализа.
4. Выдай отчёт-таблицу (формат ниже). Молчаливый no-op запрещён: по каждой
   категории — находка ИЛИ явное «ничего, потому что ...».
5. Правки — только по явному подтверждению пользователя, по одной.
6. Запиши уроки в журнал `.agents/retro/lessons.md` и обнови индекс
   `.agents/retro/index.md` (создай при первом уроке).

## Воркфлоу

### Шаг 1. Цель

- `--last` — последняя сессия текущей директории (по умолчанию)
- `--session <ses_id>` — конкретная сессия
- `--window <Nd>` — все события за N дней (тренды, накопительная статистика)

### Шаг 2. Сбор фактов

`collect.sh` печатает секции: SESSIONS (метаданные, токены, cost, субагенты),
TOOL_CALLS (частоты инструментов, точные дубли bash-команд, топ длиннейших),
LLM (модели/агенты), ERRORS (level=ERROR, stream error), SKILL_CONFLICTS
(дубли имён скиллов глобально), FILES (зоны правок), ASKING (затыки на разрешениях).

Дополни сборку контекстом текущей сессии: какие скиллы реально запускались
(инструмент `skill`), какие промпты пользователь переписывал, где ответ не попал
в задачу — этого в логах нет, это знаешь только ты из контекста разговора.

### Шаг 3. Анализ

Пройди категории из [references/categories.md](references/categories.md):
тул-экономика, скиллы и конфликты, ошибки и ретраи, навигация, no-ops,
память и граф знаний, разрешения. Каждая категория: критерий «Use when»,
типовые находки, шаблон фикса.

### Шаг 4. Отчёт

Таблица, отсортированная по severity:

```
| Severity | Категория | Находка | Предлагаемая правка | Файл/инструмент |
```

Severity: **high** (ошибки, конфликты скиллов, систематские дорогие паттерны),
**medium** (повторяющиеся неоптимальности), **low** (единичные случаи).

После таблицы — блок «Ничего не найдено»: список категорий без находок с причиной.

### Шаг 5. Правки (по подтверждению)

- Каждую правку предлагаешь отдельно и применяешь только после «да» пользователя
- Показывай diff до применения
- Ручные правки пользователя в скиллах не перезаписывать молча — только показать diff
  и предупредить
- Типы правок: SKILL.md (описание/триггеры/шаги), AGENTS.md, opencode.json/tui.json,
  сущности графа знаний (memory_* в проектах, где он есть)
- В журнал уроков не писать секреты, токены и содержимое bash-команд с кредами

### Шаг 6. Журнал уроков и индекс

Журнал — `.agents/retro/lessons.md` текущего проекта (создай при первом уроке),
формат записи:

```markdown
## [RETRO-ГГГГММДД-XXX] категория

- Дата: ISO-8601
- Сессия: ses_... (или "окно N дней")
- Урок: одна строка, что произошло
- Решение: что сделано / предложено
- Статус: pending | applied | wont_fix
- Повторы: 1 | First seen: ГГГГ-ММ-ДД | Last seen: ГГГГ-ММ-ДД
```

Индекс — `.agents/retro/index.md` (создай при первом уроке), обновляй при каждом
прогоне: строка в таблицу «Прогоны» (дата, run, область, находки H/M/L) и строки
в таблицу «Уроки» (ID, категория, краткий урок, статус, повторы, счётчик
промоушена «n/3»).

Промоушен урока в постоянные правила (правка AGENTS.md/скилла на следующем ретро):
урок повторился ≥3 раз за 30 дней ИЛИ проявился в ≥2 разных задачах ИЛИ
формулируется как «Когда X — делай Y» без привязки к проекту.

## Ограничения

- Лог — внутренний формат opencode (1.18.x), поля `message=...` могут меняться
  между версиями; при изменении — правится collect.sh
- В логах нет текста сообщений и ответов модели: анализ по действиям и метрикам
- Гранулярность tool-вызовов — `run` (процесс opencode целиком, с субагентами),
  не отдельная сессия
- `cost`/`tokens` у создаваемых сессий часто 0 — надёжные числа только у завершённых
