# Research: диагностика медленного появления окон

Проверенные факты (планирование, 2026-11-20):

## История фейда

- Коммит `4b07628` (вошёл в 2.3.1) заменил блокирующий фейд на неблокирующий:
  было `for i in range(100): attributes('-alpha', ...); time.sleep(0.006)` в
  show/hide всех трёх окон, стало `fade_window()` (`src/windows/window_fade.py`).
- Старый цикл блокировал mainloop: окно не перерисовывалось во время анимации и
  появлялось целиком при alpha=1 → фейд был невидим, казался мгновенным.
- Новый: `FADE_STEPS=100` × `FADE_STEP_MS=6` (номинально 600 мс), но таймер
  Windows ~10-15 мс на шаг → реально 1-2.5 с; шаги дополнительно растягиваются
  конкуренцией after-коллбеков с перерисовками.

## Почему окно настроек медленнее окна перерыва

| Фактор | WndBreak | WndSettings |
|---|---|---|
| Задержка до старта фейда | 0 мс — show() вызывается внутри обработки снапшота (wnd_break.py:95-96) | до 200 мс poll-очередь трея (view.py:20, 105-108) |
| Отрисовка при map | 3 виджета, fullscreen-картинка = один блит | ~15-20 видимых CTk-виджетов (canvas на каждый) |
| Нагрузка от снапшотов во время фейда | лёгкая (прогрессбар+текст) | 2 configure с картинками (wnd_settings.py:456) + 11 set() (wnd_settings.py:467-479) на каждый снапшот |

## Прочее

- `View.__apply_snapshot` (view.py:89-94) обновляет все окна на каждый снапшот,
  даже скрытые (постоянный фон-шум UI-потока).
- Внешних вызовов `View.show_wnd_break`/`hide_wnd_break` нет — единственный
  механизм показа/скрытия окна перерыва: `WndBreak.update()`; guard скрытости
  НЕ должен его отключать (иначе регресс: окно перерыва не появится).
- `deiconify()` синхронно ставит Tk-состояние `normal` → `__apply_snapshot`
  сразу после `show()` проходит guard `state() == 'normal'`.
- Паттерн кэша на изменение: `WndStatus.__configure_button_state`
  (wnd_status.py:158-160, known issue 32); `update_protection_status_image`
  не имеет кэша (wnd_settings.py:432-445).
- Тесты фейда импортируют `FADE_STEPS` и сверяют с ним
  (tests/test_window_fade.py:3,97) — адаптируются автоматически.

## Решения (подтверждены пользователем)

1. `FADE_STEPS` = 40 (пользователь выбрал 40 из 30/40).
2. Guard скрытых окон в `__apply_snapshot` — да (все пункты).
3. Свежий снапшот при открытии из трея — да; оценено: без доп. задержек
   (apply в том же тике poll, стоимость — один проход update, мс).
4. Кэш decor в `WndSettings` — да.
