# Задача: ускорить появление окон (фейд прозрачности)

## Постановка пользователя

Хочу сделать появления окон побыстрее (изменение прозрачности). В версии 2.3.1
прозрачность стала изменяться медленнее — окно дольше становится видимым.
Замечено: окно перерыва появляется быстрее, чем окно настроек.

В ходе обсуждения выбраны 3 пункта плана (все одобрены пользователем):

1. `FADE_STEPS` 100 → **40** (`src/windows/window_fade.py:8`).
2. Не обновлять скрытые окна в `View.__apply_snapshot` (WndBreak — всегда,
   его `update()` сам вызывает show/hide) + кэш `__latest_snapshot`.
3. Свежий снапшот применяется сразу после показа окна из трея (обёртки
   действий вместо сырых bound-методов в `__ui_action_queue`).
4. Кэш protection-декора в `WndSettings.update_protection_status_image`
   (паттерн known issue 32), ранний выход при неизменном статусе.

## Контекст диагноза (из планирования)

- До 2.3.1 фейд был блокирующим (`time.sleep`), mainloop не перерисовывал окно —
  окно «всплывало» сразу при alpha=1, анимация была невидима.
- С 2.3.1 фейд неблокирующий (`after()`), 100 шагов растягиваются из-за
  разрешения таймера Windows (~10-15 мс на шаг) и конкуренции с перерисовками.
- Окно настроек медленнее окна перерыва: (а) до 200 мс ожидания poll-очереди
  трея до старта фейда, (б) ~15-20 видимых CTk-виджетов на первом map,
  (в) `update()` на каждый снапшот делает 2 configure с картинками + 11 set()
  переменных; `__apply_snapshot` гоняет update всех окон, даже скрытых.
