# Решения: screen-saver-interactions

Все решения подтверждены пользователем 2026-11-19.

| # | Решение | Причина | Альтернативы (отклонены) |
|---|---|---|---|
| 1 | Детекция видео — системный флаг занятости экрана: `CallNtPowerInformation(SystemExecutionState)` → `ES_DISPLAY_REQUIRED` | Выбор пользователя; флаг поднимают браузеры/плееры при видео, включая оконное (не только fullscreen); без новых зависимостей | Fullscreen-детектор (GetForegroundWindow+GetWindowRect — ловит только fullscreen); списки процессов (хрупко) |
| 2 | Поведение при видео — реальный переход в `StepType.iddle_mode` (штатные уведомление/звук) | Выбор пользователя («Настоящий iddle_mode»); переиспользование существующей механики | Заморозка elapsed в текущем шаге без смены шага; авто-вход в `suspended_mode` (исходная формулировка task.md — пользователь переопределил в диалоге) |
| 3 | Выход из iddle — `is_user_active and not video_active` (удержание при видео, даже если пользователь активен) | Следствие решения 2: иначе активный зритель видео выбрасывался бы из iddle каждый тик | Выход только по активности (конфликт причин входа) |
| 4 | Debounce снятия «видео» ~5 тиков подряд без флага | Флаг мигает у плееров с периодическим сбросом idle-таймера; без debounce — дёрганье work↔iddle с уведомлениями | Без debounce |
| 5 | Блокировка скринсейвера — `SetThreadExecutionState(ES_CONTINUOUS\|ES_DISPLAY_REQUIRED)` на время `break_mode`, снятие при выходе; вызовы из потока контроллера | Документированный способ; поток один — требование API соблюдено | Периодический сброс idle-таймера каждый тик |
| 6 | Дефолты: `screensaver_block="on"`, `suspend_on_video="on"`, `reset_work_time_in_idle="off"` | Выбор пользователя; reset — off, чтобы не менять молча существующее поведение (сегодня время при idle сохраняется) | reset=on (меняет поведение существующих пользователей) |
| 7 | `reset_work_time_in_idle` — сброс elapsed при входе в iddle (`__set_current_step`), чекбокс на вкладке Time settings | Выбор пользователя (добавление к плану в ходе диалога); единая точка покрывает обе причины входа в idle | Сброс при выходе (эквивалентно, но семантика названия — «при переходе в idle») |
| 8 | Иконка вкладки Display: `res/img/monitor.png` с fallback на `img_gear` + `logger.warning` | Пользователь положит PNG позже; приложение не должно падать при отсутствии файла | Сгенерировать PIL-иконку |
| 9 | Ограничение детекции: видео не проверяется в `break_mode` (окно перерыва само fullscreen) и наш blocker не учитывается (release до первого опроса в том же потоке) | Корректность самонаблюдения | — |

## Снятые вопросы

- «Видео дольше 60 минут» — снят: suspended_mode не используется (решение 2), iddle не тикает.
- Уведомление при видео-idle — штатное уведомление/звук `iddle_mode` (реализация уже есть в `do_current_step_actions`).
